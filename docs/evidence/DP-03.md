# Evidência DP-03 — Jornada web mínima

**Data:** 2026-10-10 · **Base:** `90fdfe4` + alterações locais não commitadas (inclui DP-01/02) · **Estado:** implementada e verificada localmente; **não commitada, não publicada**. Teste com Gemini real hospedado pertence a DP-05 e **não** foi feito aqui.

## Decisões (registradas antes de adicionar dependências)

| Tema | Escolha | Motivo / alternativa |
|---|---|---|
| Aplicação | `web/` com **React 19 + Vite 8 + TypeScript** | Ferramentas simples e estáveis; Vite já existia na árvore (via Vitest). Sem roteador, estado global ou UI kit: rotas de 5 telas via `history` próprio, estado em hooks. Alternativas: JS puro (mais código de DOM manual) e frameworks full-stack (acoplariam o backend). |
| Testes de componente | **Vitest + Testing Library (jsdom)** | Mesmo runner do backend. Contratos simulados por um backend falso em memória (`web/src/test/fake-backend.ts`). |
| E2E | **Playwright** com o Chrome do sistema (`channel: 'chrome'`) | Evita baixar navegadores nos runners do GitHub, que já trazem Chrome. |
| Hospedagem | Mesma origem, sob `/app`, pelo backend | Elimina CORS e simplifica o deploy; API registrada antes e com precedência. |
| Gemini no E2E | Processo separado `web/e2e/fake-gemini.mjs`, o SDK apontado via `GOOGLE_GEMINI_BASE_URL` | O backend roda o código de produção sem modificação (provider, guard, ledger); o serviço público não ganhou endpoint de simulação. |
| Token | Somente em memória | Recarregar exige login; sessão demo reencontrada pela API. Nunca em URL. |

Backend (TDD, `src/web/web-app.spec.ts`): `createApp` aceita `webDistDir`; `/app/*` com CSP restritiva, `index.html` sem cache, assets `immutable`, deep link → index, arquivo ausente → 404 JSON, `/` e `/app` → `302 /app/`, rota desconhecida → `404 {status:'error'}`. Sem artefato web a API segue funcionando (aviso em log). O contrato de erro 404 JSON vale agora para qualquer rota desconhecida do serviço (antes: HTML padrão do Express).

E2E (Playwright, API real compilada + PostgreSQL 16 efêmero + Gemini determinístico), 4 cenários, todos verdes:
1. cadastro → sessão → duas notas → confirmar (CAN-A 12 → 15, CAD-A 1) → sair/entrar → persiste;
2. 429 do provedor (mensagem, estoque intacto, reenvio manual) → nota duplicada sem dupla movimentação → rejeitar (CAN-A 12, CAD-A 1, CAN-B 3);
3. reinício entrega estoque vazio; outra conta (viewport 360 px) não vê estoque alheio, sem rolagem horizontal, Tab funcional;
4. deep link/refresh e rota de API desconhecida mantêm os contratos.

## Segurança e acessibilidade

- Bundle (`web/dist`): 3 arquivos, sem sourcemap; varredura por padrões de segredo (chave `AIza…`, URL `postgres://`, JWT, nomes `INVITE_CODE`/`GEMINI_API_KEY`/`JWT_SECRET`/`DATABASE_URL`, valores do E2E) sem ocorrências. Variáveis públicas: nenhuma.
- CSP aplicada às respostas de `/app`; a UI não usa scripts/estilos inline nem `dangerouslySetInnerHTML`.
- Teclado e leitores de tela: rótulos em todos os campos, `role="alert"` com foco após erro, `role="status"` para progresso, link "Ir para o conteúdo", foco visível, alvos ≥ 44 px, `prefers-color-scheme`. Inspeção visual das capturas em desktop (1280) e 360 px: sem cortes ou sobreposição.
- **Não** foi executada auditoria automatizada de contraste/axe nem teste com leitor de tela real; a avaliação de contraste foi por escolha de paleta e inspeção.

Capturas sanitizadas (somente dados sintéticos): `docs/evidence/screenshots/dp-03-*.png`.

## Mudanças em outros pontos

- `render:build` agora inclui `npm --prefix web ci` e o build da interface (`web:install`, `web:build`); CI ganhou os jobs `web` (typecheck, testes, build) e `web-e2e`.
- `tsconfig.json` exclui `web/` (nunca emite `.js` no backend); ESLint ignora `web/**` (toolchain própria).
